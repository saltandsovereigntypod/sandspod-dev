# Living Library reconciliation readiness

`js/living-library-reconciliation.js` is a pure evidence/classification/planning authority plus an authenticated write-free scanner. Planning produces a deterministic digest, before/after counts, eligible groups, blockers, and dependency redirects. It never writes or deletes.

A future server procedure must resolve the current user from JWT, recalculate strong identities, reject stale digests, lock eligible rows, merge only non-conflicting fields, redirect relations/object instances/ritual links/Grimoire and Altar references, prevent self-relations, deduplicate exact directional relations, retire only proven duplicates, and verify no dangling references. It must preserve event histories and never touch Auth or Community content.

A reconciliation backup gate is separate from account deletion and guest migration checkpoints. Running operations must use a shared operation lock. Successful verified reconciliation may update sync time once; scans and plans must not. Current execution remains disabled because deployed schemas, Altar snapshot reference rewriting, Grimoire reference columns, and server transaction behavior are not verified.
